SQL & the T-SQL bridge

Remember the pattern, then check the result.

Shortcut / reminderUse it for
SELECT / WHEREChoose columns / filter rows before grouping.
GROUP BY / HAVINGAggregate by a defined grain / filter groups.
LEFT JOINKeep every left-hand row; watch for one-to-many multiplication.
COUNT(*) / COUNT(column)Count rows / count non-NULL values.
IS NULL / COALESCETest missing values / choose a deliberate replacement.
WITH name AS (...)Name a CTE to make query stages readable.
ROW_NUMBER / RANK / DENSE_RANKUnique sequence / ties with gaps / ties without gaps.
LAG / LEADRead a previous / next row within an ordered partition.
WITH monthly AS (
  SELECT category, SUM(revenue) AS sales
  FROM sales
  WHERE sale_date >= '2026-01-01'
    AND sale_date < '2026-02-01'
  GROUP BY category
)
SELECT category, sales,
  DENSE_RANK() OVER (ORDER BY sales DESC) AS sales_rank
FROM monthly;
  • Logical order, simplified: FROM/JOIN → WHERE → GROUP BY → HAVING → window calculations → SELECT → DISTINCT → ORDER BY → row limit. Write a CTE when you need to filter a window result.
  • T-SQL uses TOP (n) rather than PostgreSQL LIMIT n. Date functions, casts and identifier quoting vary; portable concepts do not make every query portable.
  • Use an explicit ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW frame for a row-by-row running total; order by a stable tie-breaker.
  • Before trusting a join: check key uniqueness, unmatched rows, row count and totals. Never use DISTINCT simply to conceal a broken join. Practise UPDATE/DELETE only in a safe copy.

Statistics, metrics & data quality

Keep the denominator, uncertainty and business question visible.

Shortcut / reminderUse it for
Mean / medianMean is sensitive to outliers; median is useful for skewed values.
Weighted meanSUM(value × weight) / SUM(weight); validate the weights.
Percentage change(new − old) / old; format as a percentage and define what happens at old = 0.
Percentage points30% − 20% = 10 percentage points; the relative increase is 50%.
Conversion rateConversions / eligible opportunities over a defined period.
IQRQ3 − Q1; inspect the distribution before using outlier rules.
Sample / population spreadUse STDEV.S for sample estimation; STDEV.P for the full population described.
CorrelationAssociation is not evidence of causation.
BEFORE ANALYSIS
Question → audience → metric → grain → period

AFTER EVERY TRANSFORMATION
Rows → keys → missingness → totals → exceptions

BEFORE SHARING
Source → assumptions → limits → privacy → owner
  • A p-value is not the probability that the null hypothesis is true. Explain the test assumptions, effect size and uncertainty instead of treating 0.05 as an automatic business decision.
  • A frequentist 95% confidence procedure covers the fixed true parameter in 95% of repeated samples under its assumptions; it is not a guarantee about an individual outcome.
  • Missing is not automatically zero. Investigate causes and document any exclusion or imputation. Reconcile with an independent method where possible.
  • Use only permitted public/synthetic practice data. Minimise personal information, keep raw data unchanged and document transformations and retention.

import pandas as pd
import matplotlib.pyplot as plt

sales = pd.read_csv("sales.csv")
products = pd.read_csv("products.csv")
out = sales.merge(products, on="product_id",
    how="left", validate="many_to_one", indicator=True)
assert len(out) == len(sales)
print(out["_merge"].value_counts())
summary = out.groupby("category", dropna=False)["revenue"].sum()
summary.sort_values().plot.barh()
plt.xlabel("Revenue (£)")
plt.tight_layout()
plt.savefig("revenue_by_category.png", dpi=150)
  • Example assumes the listed CSV columns exist and revenue is numeric. Resolve unmatched keys before interpreting category totals. Decide how missing revenue should be handled before summing.
  • Create a virtual environment; install required libraries and record versions. Restart the kernel and run every cell in order before sharing.
  • Python basics to recall: = assigns; == compares; indentation defines blocks; lists are ordered; dictionaries map keys to values. Use functions for repeated transformations.
  • Name chart units, period and source. Use bars for category comparisons, lines for time series and scatter plots for relationships.

Projects, capstone & handover

A repeatable workflow for every portfolio project.

Shortcut / reminderUse it for
1 · DefineWrite one useful question, its reader, the metric and success criteria.
2 · SourceRecord source, licence, date, grain and limitations.
3 · ProfileCheck types, ranges, blanks, duplicate keys and suspicious values.
4 · TransformKeep raw inputs unchanged; document and reproduce each step.
5 · ValidateReconcile counts, joins and key totals independently.
6 · ExplainShow three findings, an actionable recommendation and limits.
7 · DeliverPackage the workbook/query/report/notebook, README and screenshots.
8 · HandoverExplain refresh, access, definitions, exceptions and who owns failures.
CASE STUDY IN SIX LINES
Question: What decision does this support?
Data: Where did it come from and what does one row mean?
Method: What did I change or calculate?
Checks: How do I know the result is sound?
Finding: What changed, by how much, over which period?
Limit: What can this analysis not establish?
  • Portfolio ladder: retail Excel → retail SQL → retail Power BI → public NHS pandas analysis → end-to-end regional capstone. Lead with your strongest three pieces.
  • Public healthcare projects need dataset definitions, reporting-period rules and published methodology. They do not prove experience with internal clinical systems.
  • Use screenshots, a PDF and a short demo if live sharing is unsuitable. Never use Publish to web for confidential or personal data.
  • Label synthetic work honestly. Describe what you built and verified; do not claim fictional savings, workplace deployment or business impact.
